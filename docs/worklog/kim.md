**바뀐 것**
- API·응답 형식: 문서 관리 role 쿼리(기본 citizen), GET limit(기본 100, 최대 1000), 문서 응답 deletable 추가. POST·PUT·DELETE는 admin만 허용.

**확인한 것**
- 전체 pytest 131개 통과(131.51초). 초기 13개 실패는 ortools 미설치였고 설치 후 전체 재실행.
- 문서 전용 테스트 12개에 정책 변경 시 인덱스 재사용, 기본 문서 보호, 저장 경로 분리, 이전 운영 목록 호환, 역할별 관리 거부를 포함.
- 프런트엔드 프로덕션 빌드 통과. 기존 번들 크기 경고는 남음.
- 격리 브라우저에서 실제 상태에 맞는 색인 갱신 안내와 검색 후 상태 해제를 확인.
- 격리한 브라우저에서 시민의 패널 비표시, 관리자의 업로드·수정·삭제, 기본 파일 삭제 버튼 없음, API 403, 운영 파일 저장 위치 확인.
- 실제 BGE로 법규 평가 질문 20개에 대해 dev와 수정 코드의 found·sources가 모두 동일함. 결과는 eval/results/kim_review_retrieval_20261119.json.
- Git 제외 경로와 파일명을 git check-ignore로 확인.
- 검증용 합성 모델을 최신 dev 코드로 학습했으며 이 PC의 과도한 병렬 실행을 줄이기 위해 검증 프로세스에만 n_jobs=2를 적용함.

**확인하지 못한 것**
- Qwen 답변 재평가를 추가 시도함. 실제 BGE 근거 20개를 먼저 준비하고 검색 모델을 종료한 뒤 CPU 모델을 실행했으나, bfloat16 실행은 첫 문항이 수 분 동안 끝나지 않아 중단함. 이어 동적 int8 실행도 첫 문항에 수 분이 걸렸고 A1은 오답이어서 중단함. 기본 CPU float32와 다른 실행 조건이므로 품질 회귀 판정에 사용하지 않음. 전체 답변 평가는 미완료이며 실험 결과는 eval/results/kim_review_qwen_20261119.json에 complete=false로 기록함. OpenAI 키는 D드라이브 작업본들에 설정되어 있지 않음.
- 기존 사용자가 docs/bus에 올렸던 파일의 자동 이관은 수행하지 않음. 이 PC의 D:/dispatch-ai 및 D:/dispatch-ai-f36-f37에는 운영 목록과 미추적 docs/bus 파일이 없어 이관할 업로드가 발견되지 않았음.
