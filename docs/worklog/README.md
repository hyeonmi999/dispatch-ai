# 작업 기록

각자 한 작업을 날짜별로 남기는 곳입니다. 계획서(`docs/plans/`)가 "무엇을 할지"라면, 작업 기록은 "실제로 무엇을 했고 어떻게 확인했는지"입니다. 다음에 이어서 일하는 사람(본인, 팀원, AI 도구)이 여기부터 읽습니다.

| 담당 | 파일 |
|---|---|
| 오정훈 | [oh.md](oh.md) |
| 박성훈 | [park.md](park.md) |
| 김주혜 | [kim.md](kim.md) |

## 규칙

- **작업을 끝낼 때마다** 자기 파일 **맨 위**에 한 건을 추가합니다 (최근 기록이 위). AI 도구로 작업했다면 AI가 씁니다 ([AGENTS.md](../../AGENTS.md) 4장).
- 하루에 여러 번 작업했으면 같은 날짜 아래에 이어 써도 되고, 주제가 다르면 따로 써도 됩니다.
- **한 것만** 적습니다. 할 예정인 일은 "다음 할 일"에만 적습니다.
- **확인한 방법과 숫자**를 적습니다. "테스트 통과"가 아니라 "pytest 53개 통과"처럼 씁니다. 확인하지 못한 것은 "확인하지 못한 것"에 그대로 적습니다.
- 남의 기록은 고치지 않습니다. 틀린 내용을 발견하면 자기 기록에 적거나 PR 댓글로 알립니다.
- 비밀값(API 키, 비밀번호)은 적지 않습니다.
- 작업 기록 파일은 그 작업의 PR에 함께 넣습니다.

## 형식

아래를 복사해 맨 위(제목과 안내 문단 바로 아래)에 붙이고 채웁니다. 해당 없는 칸은 "없음"이라고 적습니다.

```markdown
## YYYY-MM-DD · <한 줄 제목>

- **브랜치 / PR**: `feat/<이름>-<기능>` · #번호
- **계획서 Task**: `docs/plans/<파일>.md` Task N

**한 일**
- <기능·수정 단위로. 왜 했는지 한 마디>

**바뀐 것** (남이 영향받는 부분)
- API·응답 형식: <없음 / 무엇이>
- DB: <없음 / 새 테이블·컬럼 변경 → 로컬 DB 재생성 필요 여부>
- 의존성·환경: <없음 / 패키지, .env 변수, 받아야 하는 데이터>

**확인한 것**
- <무엇을 어떻게 돌렸고 결과가 어땠는지. 숫자 포함>

**확인하지 못한 것**
- <없음 / 무엇을, 왜>

**다음 할 일**
- <이어서 할 일, 기다리는 것>

**팀원이 알아야 할 것**
- <없음 / 받은 뒤 해야 하는 일, 주의할 점>
```
