## 2026-11-22 · 배차 엔진 다음 작업 P-1 확인 · P-2 최적화 이력 · P-3 길안내 시간 기준 · P-4 성능 비교 화면

- **브랜치 / PR**: `feat/park-next` · (PR 전)
- **계획서 Task**: [docs/plans/park-next.md](../plans/park-next.md) Task P-1~P-4

**한 일**
- P-1 확인: 오정훈이 옮긴 `BusAdapter.simulate()`·`optimize()`를 읽고, 메서드와 API가 같은 값을 내는지 테스트 1건 추가
- P-2: `POST /api/bus/optimize`가 실행마다 `optimization_run`에 한 줄 저장하고 `run_id`·`db_saved`를 돌려줌. 계산은 스레드에서 돌려 다른 요청을 막지 않음. `GET /api/bus/optimize/runs` 추가. 최적화 화면 아래에 "최근 실행 기록"(펼칠 때만 불러옴)
- P-3: 길안내가 구간 혼잡도·배차간격을 "그 시각에 탈 정류장에 오는 버스가 기점을 떠난 시간대" 값으로 읽게 함 (`BusAdvisor.departure_hour`, `legs[].start_hour`). 갈아탄 뒤 구간은 앞 구간의 걷기·대기·탑승 시간만큼 지난 시각으로 계산. 11-13에 혼잡도 시간 기준을 바꾸면서 길안내를 같이 고치지 않았던 것
- P-4: `GET /api/bus/backtest`(결과 파일을 읽기만 함, 기존 `app/domains/bus/backtest.py`에 추가)와 "배차 방식 비교" 패널. "분석" 화면 배치에 넣음
- 위 작업 중 발견: 서버가 뜬 뒤에 DB가 꺼지면 이력 조회가 500 → 503과 이유로 바꿈
- 지난 기록(PR #1) 고침: 머지 상태, 규칙 방식 과밀 비율(11.47% → 최종 12.12%), 확인하지 못한 것

**바뀐 것** (남이 영향받는 부분)
- API·응답 형식: `POST /api/bus/optimize`에 `run_id`·`db_saved` 추가(기존 필드 그대로). 새 API `GET /api/bus/optimize/runs`, `GET /api/bus/backtest`. 길안내 `legs[]`에 `start_hour` 추가, **길안내 구간 혼잡도·배차간격 값이 바뀜**(노선 중간부터). `docs/contracts.md` 2·2-1·2-2·3-1 갱신
- DB: 새 테이블·컬럼 없음 (`optimization_run`은 오정훈이 만든 것을 씀). 로컬 DB 재생성 불필요
- 의존성·환경: 없음. 설정 `OPTIMIZE_RUNS_LIMIT`, `GUIDE_CLOCK_MINUTE`, `EVAL_RESULTS_DIR`, `BACKTEST_RESULT_PATH` 추가. `scripts/backtest.py`는 결과 경로를 config에서 읽음

**확인한 것**
- `python -m pytest -q` 155개 통과 (dev 140개 + 새 테스트 15개: 최적화 이력 6, 메서드 = API 1, 길안내 시간 기준 4, 성능 비교 API 4)
- `npm run build` 성공
- 서버·화면을 띄워 직접 호출: 최적화 1회 → `run_id` 1·이력 조회에 보임, `limit=101`은 422, DB를 끄고 최적화 → 결과 그대로 `db_saved: false`, DB를 끈 채 이력 조회 → 503. 성능 비교 API·화면 5행이 `backtest.json`과 같음(현행 20.66% · 규칙 12.12% · 그리디 8.70% · 최적화 8.31% · 감차 허용 8.57%)
- 길안내 실데이터: 150번 금하마을 → 종로2가 8시 혼잡도 0.202 → 0.951 (기점 5시 출발 버스). 5개 노선 × 5곳 비교에서 8시 25곳 중 20곳이 다른 시간대를 읽고 차이 평균 0.128, 18시 0.148 (`eval/results/guide_time_basis_1·2.json`)
- 길안내 경로 수 (실데이터 30쌍, 바꾸기 전 → 후): 8·14시 같음, 5시 예측 노선 구간 36 → 19개(첫차가 아직 오지 않은 노선 중간 정류장을 빼게 됨), 23시 0 → 32개(막차 무렵 경로가 사라지던 것이 나옴). 오류 0건

**확인하지 못한 것**
- 길안내 팝업·챗봇 길안내 답변을 화면에서 눌러 보지 않음 (API 응답과 테스트로만 확인)
- 기점 → 정류장 소요는 시간표 기반 어림이고 출퇴근 1.15배(가정값)를 씀. 실제 통과 시각 자료와 비교하지 못함
- 좁은 화면에서 성능 비교 표는 옆으로 넘겨야 보임 (넓은 화면은 확인하지 않음)
- 기존 이력 API(`GET /api/advisories` 등)도 DB가 중간에 꺼지면 500일 수 있음 (확인하지 않음)
