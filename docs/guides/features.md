# 기능 목록

모든 기능에 ID를 붙였습니다. 구조도와 개인 가이드는 이 ID로 기능을 가리킵니다. F-0x는 이미 있는 기능, F-1x·2x·3x는 이번에 새로 만들 기능입니다.

## 이미 있는 기능

| ID | 기능 | 하는 일 | 입력 → 출력 | 위치 |
|---|---|---|---|---|
| F-01 | 승차·날씨 데이터 수집 | 서울시 승차·운행 기록, 날씨, 노선 좌표를 받아 저장 | 공공데이터 API → `data/` | `scripts/download_seoul_bus.py`, `fetch_weather.py`, `fetch_route_geo.py` |
| F-02 | 승객 수 예측 | 노선·정류장·시간대별 승객 수를 21일 앞까지 예측 | 노선·날짜·시간 → 예상 승객 | `POST /api/bus/predict`, `app/domains/bus/forecaster.py` |
| F-03 | 구간별 혼잡도 계산 | 버스 1대당 승객 ÷ 정원(55명)으로 구간별 혼잡 정도 계산 | 예상 승객 + 운행횟수 → 혼잡도 | `app/domains/bus/advisor.py` `analyze_day()` |
| F-04 | 규칙 기반 배차 권고 | 혼잡도 0.8 이상이면 증차, 0.25 미만이면 감차 검토 | 노선·시간 → 권고 간격·근거 | `POST /api/bus/advise`, `/advise/all` |
| F-05 | 법규 질의응답 (RAG) | 법령·조례에서 근거 조항을 찾아 답변, 없으면 "찾을 수 없음" | 질문 → 답변 + 출처 | `POST /api/bus/ask`, `app/core/rag.py` |
| F-06 | 대시보드 화면 | 지도, 24시간 그래프, 권고 카드, 이력 패널 | API 응답 → 화면 | `frontend/src/` |
| F-07 | 권고 검토·이력 | 권고마다 담당자가 승인·보류·반려를 누르고, 그 상태를 권고 기록 테이블(`advisory_log`)에 저장 | 권고 → `advisory_log` | `POST /api/advisories/{id}/review` |

## 새로 만들 기능

난이도는 바이브 코딩 기준입니다. ★ 문서·설정 위주 · ★★ 기존 코드 재사용, 파일 1~2개 · ★★★ 새 기능 + 화면 또는 여러 파일 · ★★★★ 여러 기능 연결, 검증이 까다로움 · ★★★★★ 새 개념 학습 필요, 막히기 쉬움

| ID | 기능 | 하는 일 | 입력 → 출력 | 위치 | 담당 | 난이도 |
|---|---|---|---|---|---|---|
