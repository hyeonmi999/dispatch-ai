## 준비

- 로컬 전용 서버·화면을 실행하고 모델은 BGE·로컬로 선택합니다. LLM 전체 평가와 서버를 동시에 실행하지 않습니다.
- 기본 docs/bus 원본은 지우지 않습니다. 시연용 TXT는 업로드 경로(data/docs/bus/)에만 저장하며 Git에 올리지 않습니다.
- 같은 이름의 기본 파일이 없는지 확인합니다. 중복 409가 나오면 관리자 안내의 파일명을 확인하여 폴더에서 이름 충돌을 해소합니다.
- 테스트 문서는 실제 법규가 아님을 제목과 내용에 표시합니다. 아래 토큰은 프로그램 갱신 점검용이고 법적 기준이 아닙니다.

## 실제 법규가 개정됐을 때

1. 공식 출처의 개정 원문·시행일·적용 대상을 확인하고 PDF 본문이 추출되는지 확인합니다.
2. 기존 원본을 화면에서 지우지 않고 새 버전을 구분되는 파일명으로 등록합니다. 제목·등급·출처·받은 날짜를 기록합니다.
3. 기존 버전은 사용 중지하고 새 버전만 해당 질문의 근거가 되도록 합니다. 시행 전후 버전이 필요한 질문은 적용 시점을 명시합니다.
4. 같은 질문의 변경 전후 출처·본문을 비교합니다. 등록 직후 색인 갱신이 필요할 수 있습니다.
5. 바뀐 조항을 반영한 문제집으로 회귀 검사하고 실제 평가 결과를 저장합니다. 팀 공유할 공개 법규는 출처 목록과 함께 별도 PR로 올립니다.

정식 법규를 임의로 고쳐 개정 자료처럼 시연하지 않습니다. 위 TXT는 ‘교체가 검색에 반영되는지’만 보여 주는 기능 점검입니다.
